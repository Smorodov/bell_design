# Запуск оптимизации колоколов — краткое руководство

## Сборка

Из корневой папки проекта:

```bat
build.cmd
```

Затем при необходимости отдельный запуск тестов:

```bat
test.cmd
```

`build.cmd` только конфигурирует и собирает проект. Он не запускает CTest.

## Готовые варианты

Запускайте по одному из корневой папки:

```bat
run_western_220.cmd
run_western_440.cmd
run_western_880.cmd
run_orthodox_220.cmd
run_orthodox_440.cmd
run_orthodox_880.cmd
```

Или универсальным файлом:

```bat
run_bell_case.cmd western 440
run_bell_case.cmd orthodox 440
```

`run_all_demo_cases.cmd` запускает все шесть вариантов последовательно. Полный пакет может выполняться долго: западный профиль использует 50 особей и 50 поколений.

## Где искать результаты

Каждый вариант работает в отдельной папке:

```text
runs/
  western_220Hz/
  western_440Hz/
  western_880Hz/
  orthodox_220Hz/
  orthodox_440Hz/
  orthodox_880Hz/
```

Внутри будут копии `evolution.json` и `targets.json`, результат `best_geometry.json` и папка `audio/` с WAV-файлами. При использовании внутреннего FEM-решателя файл `best_bell.dat` не гарантируется: он копируется только тогда, когда решатель создал исходный `.dat`-файл.

Повторный запуск того же варианта подхватывает существующий `best_geometry.json` как начальное приближение. Для чистого старта удалите или переименуйте только соответствующую папку `runs/<profile>_<frequency>Hz`.

## Что означают частоты

Целевой профиль использует schema v2: `frequency_targets` и `amplitude_targets` задают списки целей переменной длины, а `frequency_reference` и `reference_mode` задают опорные индексы. Сейчас поддерживается `sorted_index`; он адресует отсортированные моды или сгруппированные частотные слоты, но не доказывает физическую принадлежность к модальному семейству. Геометрическое семейство начальных форм задаётся отдельно через `evolution.seed_family`. Подробности и ограничения — в `docs/PROJECT_GUIDE.md`.

## Православный экспериментальный профиль

Православные конфигурации теперь используют не западные интервалы, а экспериментальные частотные отношения, измеренные для колокола Сысоя Ростовского Успенского собора: `[0.51, 1.26, 1.64, 2.19]` относительно F2 (F2 принимается за Prime). Источник: И. Алдошина и А. Никаноров, AES 108th Convention, preprint 5117 (2000), таблица 1.

Это **один исторический образец**, а не универсальный закон настройки русских православных колоколов. Поэтому профиль явно назван `russian_orthodox_sysoi_2000_experimental`. Амплитудные веса отключены: опубликованные уровни звукового давления зависят от удара и времени после удара и не являются универсальными модальными целями. Геометрическое семейство начальных форм задаётся отдельно через `evolution.seed_family`; target JSON описывает только акустические цели.

Православный поиск теперь использует 50 особей × 50 поколений, как западный демонстрационный профиль, и фиксированное начальное зерно для повторяемости. Это выравнивает вычислительный бюджет демонстраций, но само по себе не доказывает качество оптимизации. Для обобщённой православной модели потребуются спектры нескольких репрезентативных русских колоколов и отдельная валидация.

## Пользовательские акустические профили

Для новых профилей используйте формат v2 с произвольным числом целей и явными селекторами `sorted_index`. Пример: `examples/target_profiles/custom_v2_example.json`. Старые профили v1 остаются совместимыми и сохраняют прежнее сопоставление четырёх частотных и четырёх амплитудных целей. Другие типы селекторов (семейства мод и вырожденные группы) пока не поддерживаются.

## Создание звуковых файлов

После успешной оптимизации каждый запуск автоматически создаёт в своей папке `audio/` два WAV-файла:

- `*_modal.wav` — модальный синтез-прослушивание по сохранённой геометрии (модальный расчёт выполняется заново, оптимизатор не запускается);
- `*_contact.wav` — синтез локального удара с расчётом контактного воздействия.

Рядом сохраняются спектральные/метаданные-файлы, если их создаёт соответствующая команда. Это два разных сценария возбуждения, поэтому их звучание не следует считать взаимозаменяемым. Текущие синтезаторы и контактная модель остаются приближёнными; WAV — сравнительные демонстрации, не калиброванный прогноз SPL.

## Ручной запуск с собственными конфигурациями

```bat
bell.cmd optimize --solver=internal --workdir bells --evolution evolution_orthodox.json --targets targets_orthodox.json
```

Каждая независимая оптимизация должна иметь собственную рабочую папку: оптимизатор сохраняет `best_geometry.json` и может загрузить существующую геометрию как начальное приближение. `best_bell.dat` появляется только если используемый решатель передал исходный файл модального расчёта; внутренний решатель не обязан его создавать.
